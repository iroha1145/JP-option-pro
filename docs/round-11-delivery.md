### 值得单独说明的几处

**跳空突破**：改成返回**有序转移列**而非单一目标。`WATCHING → TRIGGERED → EXTENDED`
两段一次记完。附带发现并修复：确认判定原本只在 `TRIGGERED` 时计算，导致**同样一天的
行情**，新检出的事件能到 CONFIRMED、已存在的观察事件只能到 TRIGGERED。

**风险减分**：拆成 `raw_ranking_score / risk_penalty / final_ranking_score`，排序、分层、
分类统一用 final。`ranking_score` 保留为兼容字段但改为最终值。

**波动率的双重处理**：修复 6 时发现 ATR 被 `profile_fit` 奖励（进取档）又被
`risk_penalty` 惩罚，同一属性一边褒一边贬，三档差异互相抵消。现在偏好性维度
（波动率、常规回撤深度）只在 `profile_fit`，`risk_penalty` 只保留对谁都不利的项
（200日线下、真空型、流动性边缘、极端回撤、信用规制）。ATR 提示保留为不影响排序的展示标记。

**成交额稳定性**：改为对数成交额 MAD + 前两日占比 + 无量日比例，**加权几何平均**。
算术平均下「平时200万・两天300亿」这种股票拿 70 分（58 天数值相同 → MAD≈0 → 离散度满分
把集中度的 0 分平均掉了）；几何平均下为 25 分。

**信用规制**：数值区分（001/002/003/004/101）经生产全量 72,150 行核对，
是 `PubReason` 命名布尔位的再编码（001↔JSF 系 59,377 完全一致、002↔DailyPublication
9,350 完全一致、003/004↔Restricted、101↔UnclearOrSecOnAlert），因此以**自描述的标志位**
为准。三值：名单**新鲜**时不在名单 = 无规制；名单**过期**时不在名单 = 未知，绝不当作无规制。
生产 DB 两种存储格式并存（Python dict repr 与规范化字符串），解析器两种都读。

**扫描上限**：落实为**新建事件**上限，按信号强度排序后截断，并返回
`events_detected / events_dropped_by_cap / new_event_cap`。既有追踪中的事件不受上限影响。

## 4b. 股票分割：审计清单外的最严重一项

§十二 要求测「股票分割」。测的时候发现 **`adj_close` 在全部 10,110,652 根日线上都是 NULL**。

不是同步漏了——**一括配信 CSV 根本没有 AdjO/AdjH/AdjL/AdjC 这几列**：

```
CSV 列: Date, Code, O, H, L, C, UL, LL, Vo, Va, AdjFactor
REST 列: ... O, H, L, C, AdjFactor, AdjO, AdjH, AdjL, AdjC, AdjVo
```

REST 返回算好的调整价，CSV 只给系数、要求消费方自己算。映射器读的是 `AdjC`
（REST 有、CSV 没有），所以回填全部落回生值。**与上一轮 Tick 的
`TradingVolume` vs `Vo` 是同一类问题**：同一数据集在两条通路上字段名不同。

### 实际后果

| | |
|---|---|
| 会社行动件数（10 年） | **2,600 件** |
| 涉及证券 | **1,959 / 5,383（36%）** |
| 1:2 分割 → 生值表现 | 前日比 **−50%** 的暴落 |
| 10:1 合并 → 生值表现 | 单日 **+900%** 的急涨（440 次） |

实例：`14140` 在 2019-06-26 分割，收盘 7,650 → 3,700，生值里是一次
**−51.6% 的暴跌**——而它从未发生。这些股票的 52 周高值、最大回撤、
各周期收益**全部是错的**。

### 规则（与 J-Quants 自己的 AdjC 对账确认，不是猜的）

```
调整后(t) = 生值(t) × Π{ factor(d) : d > t }
```

用 `76780`（2026-07-30 factor 0.5）验算：`6330 × 0.5 = 3165`，
J-Quants 的 `AdjC` 正是 **3165**；分割当日及之后不缩放。
`14140` 也对得上（分割前累积 0.125，因为其后还有分割）。

### 实现取舍

**在读取时计算，不回填列**。回填的话每来一次新分割就要重写全部历史行，
漏一次就留下过期的调整值。

**只在加载窗口内算即可**：窗口之外（更晚）的调整对窗口内所有 bar 是同一个系数，
在收益率与比值里相互抵消。而窗口最后一根没有「之后的调整」，
所以**最新价保持生值**——画面显示价与可执行价的语义不变（doc §五）。

成交量反向调整，成交额不动（分割不改变成交金额）。已存的 `adj_*` 优先，
不二次调整。系数超出 1e-4~1e4 视为数据异常而忽略。

### 对回测的影响

发现时首轮走步验证已跑到 80/230——**那批快照是在未调整价格上算的**。
已停止，`REPLAY_VERSION` 升到 v2（新 run_id `4758c2b4…`，不会与污染的
`a27decf4…` 混在一起），在修复后的价格上重跑。

测试 219 → 232。新测试在旧行为下**确认失败**，症状与实测一致：
`-50.0% 暴落` / `併合が 20 日リターンに残っている` / `MAE -50.5%`。

## 5. 盘中行情提供器重构

```
Quotes API → IntradayQuoteService → Registry
                                     ├─ KabuStationRelayProvider   (契约骨架・未接続)
                                     ├─ MarketSpeedRelayProvider   (契約骨架・未接続)
                                     ├─ YahooDelayedProvider       (稼働中)
                                     └─ DisabledProvider
```

每条报价携带 `source / quote_time / received_at / delay_class / is_official /
is_realtime / stale / market_session / error`。

- **两个时间戳**：单有一个无法区分「供应商停更」和「我方抓取停了」。
- **stale 按等级判定**：延迟源 15 分钟不算过期，自称实时的 12 分钟算。
- **未接通的实时源 `available=false`**，绝不会被选中后一直返回空。
- 业务层不再出现供应商名字，有测试守着（在 provider 层外 grep `yahoo_quotes`）。

**未来接券商行情需要改什么**：只需新增一个实现 `IntradayQuoteProvider` 协议的类并注册。
业务层、API 路由、前端**都不需要改**——`delay_minutes` 与文案已改为从提供器申告推导，
接上实时源后界面会自动从「延迟15分・非官方」变成「实时・官方」。

## 9. 回测与走步验证基础设施

`backend/app/research/`：`replay.py`（点时断面）、`outcomes.py`（结果）、
`walk_forward.py`（滚动窗口 + 单调性）、`runner.py`（可恢复批处理）、`__main__.py`（CLI）。

**点时语义收敛到一个闸门** `bars_up_to()`。平台检测仍排除当日（否则当日高点成为自己的
阻力，突破判定自明成立）。有一条测试专门追加未来数据后断言过去评价**逐字节不变**——
先读只会让结果变好、不会抛异常，测试是唯一防线。

**全部窗口按交易日**。结果含 1/3/5/10/20 日收益、相对 TOPIX / 行业超额、
用高低点（非收盘）测的 MFE/MAE、最大回撤、+1R 与 -1R 谁先到。
**同日两边都触及时判为 stop**——日线无法判定先后，不往乐观方向倒。
窗口数据不足标 `truncated` 且收益为 None，不把短窗口当完整窗口报。

**结论只看单调性，不看峰值**。样本 < 30 的分层标为不可靠、**排除出判定但仍然打印**
（删掉会让上层看起来很干净）。可用分层不足 3 个返回 None（判定不能）而非猜测。
只有 80% 的窗口都单调才给 `monotonic`，且报告里带一句：其他结论下不得把 0–100 分
描述为具有概率意义。

Run 按参数 + 评分版本哈希，重跑幂等；**改评分版本会开新 run，不覆盖历史**。
按日期 checkpoint，可中断续跑。独立 `jp-research.db`，不与服务库争用。

**点时限制随每份报告输出**：业种与市场区分只有当前断面，中途变更过分类的股票会被
按今天的业种归集。这在只有一份 J-Quants 主数据快照时无法解决，因此**申报而非隐藏**。

## 13. 尚未解决的真实限制

1. **业种/市场区分无点时版本**。J-Quants 只提供当前主数据断面，历史评价会按今天的
   业种归集。已在每份研究报告的 `point_in_time_limits` 中申报。
2. **市场状态门控数值无历史证据**。`GATES_VALIDATED = False`。
3. **风格价差缺日股基准**。只确认 TOPIX(0000)、Core30(0028) 有数据；
   Growth/Standard 的指数代码未确认。`2516.T` 跟踪的是 Growth **250**，是另一个指数，
   不能当作 Growth 全体的代理。
4. **Yahoo 仍然不能称为实时**：实测延迟恰好 15.0 分钟（个股、指数、ETF 一致）。
   刷新频率 ≠ 数据新鲜度。它只用于显示与「相对昨夜固定关键位的位置」叠加，
   不进入任何评分。
5. **信用规制的订正**：同一申込日的再公表会覆盖，历史回放看到的是最新版而非当时初报。

## 14. 首批历史验证结果
