# PR #17 收尾修复范围与验证方法

基线：`fe3403875f78a41e60d74a124a627f533a73781a`。本次追加修复，不覆盖原 UI 工作，不合并或部署。

## 补齐的保护

- 日股证券代码保留字母及有意义的第五位；不再用“提取数字”匹配不同证券。四位展示代码与五位普通股代码仍可对应。
- 所有者更新、手动筛选、自动核验分别管理在途状态与版本；身份改变、卸载及更新启动会使旧回调失效。未提交的条件不被读回覆盖。
- 动作必须真实终止，发布编号、日期和实际评分版本精确匹配，质量状态合格，才报更新成功。运行超时保留动作编号，后续核验不重复提交全池任务。允许短暂读回延迟的有界只读重试。
- 强制日线/指数同步可重新核验已到目标日的检查点，防止部分抓取或同日更正永远被检查点跳过；正常 GET 不触发供应商，普通同步保留既有检查点行为。
- 计算指纹覆盖清洗后历史、指数序列、相关主数据/监管/信用和计算配置，不只依赖末价或少数指标。完全相同输入仍复用原发布。
- 普通筛选恢复依据发布编号，而非仅看日期；同日强度已发布、筛选失败时仍会补齐对应版本和成功记录。拒绝旧目标的检查在雷达可见副作用之前。
- 重试状态的写入/清除遵循生产租约与围栏令牌；耗尽后回到正常日程，不被遗留的短间隔重新唤醒。
- 当前日历无记录时是未知，不以“只差一两天”认证新鲜。缺失/陈旧指数如实降级。异常旧发布元数据既不能认证新鲜，也不能永久阻挡正常恢复。
- 筛选的行、统计和日期来自同一个显式读事务；HTTP 实体标签包含影响视图的参数，不能将另一组筛选的响应判为未变。

不改评分权重、行情供应商、生产认证策略、图表画线或布局。保留 Grok 已恢复的 `/home`、雷达零命中提示与跨股票数据绑定。

## 测试证据的边界

`tests/test_pr17_final_review.py` 直接导入完整仓库的生产模块，使用正式临时 SQLite 模式和受控输入；前端新增用例调用已接入页面的实际判定及证券标识函数。失败基线和通过日志另存附件，不能用测试新增符号缺失作为业务缺陷证据。

`browser-tests/` 使用真实 Chromium、生产前端、正式本地 API、持久动作队列和独立工作进程。主成功及供应商失败恢复用例经过真实 J-Quants 映射、同步、清洗、评分、事务发布与页面读回；供应商传输与时钟可控，无关财务/新闻同步为替身。其他竞态用例明确拦截指定 HTTP 响应以控制顺序，不冒充真实供应商集成。路由检查覆盖中/日/英及桌面/移动视口，属于渲染与溢出检查，不声称所有页面完成像素级验收。

`browser-tests/container-smoke.sh` 独立构建生产镜像，以一次性数据卷启动 API/Worker；验证非 root、只读根目录、只读查询、WAL 和发布读取。运行容器采用 `--network none`、不暴露端口、没有生产凭据。它是容器启动与权限验证，不把无密钥启动说成外部行情连通性验证。

新增浏览器与容器检查纳入原 CI。最终通过数量、候选及被测提交、CI 链接与附件在 PR 评论中记录；本文不预先宣称尚未结束的检查已通过。测试集之间有包含关系，专项与全套数量不得重复累加。
