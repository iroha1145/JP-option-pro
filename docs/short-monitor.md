## 1. J-Quants が実際に返す列（推測ではなく実測）

`/markets/short-sale-report` の一括配信 CSV を 1 本開いて確認した列:

```
DiscDate  CalcDate  Code  SSName  SSAddr  DICName  DICAddr  FundName
ShrtPosToSO  ShrtPosShares  ShrtPosUnits  PrevRptDate  PrevRptRatio  Notes
```

| 列 | 保存先 | 使い道 |
| --- | --- | --- |
| `CalcDate` | `position_date` | 残高の基準日。**これで信号を立ててはいけない** |
| `DiscDate` | `published_date` | 市場が知りうる日。点時セマンティクスの起点 |
| `SSName` | `raw_holder_name` | 機関実体の正規化入力 |
| `SSAddr` | `holder_address` | 同名別法人の切り分け |
| `DICName` / `DICAddr` | `manager_name` / `manager_address` | 投資一任契約の相手方（報告主体 ≠ 運用者の切り分け） |
| `FundName` | `investment_fund_name` | 実データの 99.3% が `-`。残り 2,094 件に実名 |
| `ShrtPosToSO` | `short_ratio` | 発行済株式数に対する比率 |
| `ShrtPosShares` | `short_shares` | 株数 |
| `PrevRptRatio` | `previous_ratio` | 前回報告値。変化幅はここから取る |
| `Notes` | `notes` | 下記参照 |

`Notes` の実測分布（279,738 件時点）:

| 値 | 件数 | 意味 |
| --- | --- | --- |
| `-` | 237,192 | 特記なし |
| `顧客取引に係るヘッジポジション…を含む` | 40,753 | **顧客取引のヘッジ**。方向性の売り建てと同じには読めない |
| `Below the threshold` | 486 | 閾値割れの最終報告 |
| `変更` / `Change in holding percentage` | 468 | 訂正 |
| `報告遅延のため` | 210 | 遅延報告 |

ヘッジ明記の建玉には `is_hedge_disclosed` を立て、画面にも「含对冲持仓」と出す。

**発行済株式数は `securities` に無い。** 比率と株数は報告に両方入っているので、
指標の計算には要らない。株数を出来高で正規化する（ADV20）方針にしたのはこのため。

### 開示ラグ（実測、10 年 140 万件）

| 公開日 − 仓位日 | 件数（2025-06 以降の 28 万件で計測） |
| --- | --- |
| 1 日 | 45,434 |
| 2 日 | 124,546 |
| 3 日 | 16,425 |
| 4 日 | 75,064 |
| 5 日 | 13,999 |
| 6–7 日 | 3,901 |

最頻は 2 日、次が 4 日。10 年ぶんを入れると **最大 13 日** の例も出る
（3905 だけで 1/2/3/4/5/6/7/9/10/12/13 日の全部が観測される）。
`position_date` を信号日に使うと、その日数ぶんの未来情報を過去に流し込む
ことになる。`effective_trade_date` は「**公開日より厳密に後**の最初の営業日」
—— JPX の公表は当日 16:00 締めの受付分（取引終了後）なので、公開日当日の
終値は「その情報で取れた値段」ではない（第十三轮 P0-2）。

### 訂正

同じ `(code, calc_date, holder)` で `DiscDate` が複数あるものが訂正。実測 212 組。
元の報告は消さずに残し、後から出たほうに `correction_status = correction` を付ける。
断面は「締切以前で最も新しい公開日」を採るので、訂正が公開される前の断面に
訂正後の値は漏れない。

## 2. 「公开可见机构空头」が総空头ではない理由

報告義務はイベント駆動:

* 0.5% を超えたときに義務が生じる
* 以後 0.1% 以上動くたびに報告
* 0.5% を割ったら **最終報告を 1 本**出して義務が消える

したがって:

* **0.5% 未満の建玉は最初から見えない**
* 閾値を割った後の建玉は「その値以下のどこか」で、ゼロかもしれない
* 見えているのは常に総空売り残高の **下限**

実データでの例（3905, 2026-08-03 時点、10 年ぶん）: 24 の保有者の最新値を
単純合計すると **9.62%**。そのうち直近に更新のある報告義務中は **2 社 2.30%**
だけで、17 社は閾値割れ、5 社は解消または報告停止。足すと
**いない売り方を数えることになる**。

この理由で、DB・API・画面のどこにも `total_short_*` という名前を置かない。
`visible_*` / `reported_*` のみ。

状態は 5 つ:

| 状態 | 意味 | visible_* | reported_in_scope_* |
| --- | --- | --- | --- |
| `reporting`（新しい） | 報告義務が続いていて、直近に更新がある | **入れる** | **入れる** |
| `reporting` + `stale_reporting` | 閾値は割っていないが報告が止まっている | 入れない | **入れる** |
| `below_public_threshold` | 0.5% 割れの最終報告。実際の値は不明 | 入れない | 入れない |
| `closed` | 明示的にゼロと報告 | 入れない | 入れない |
| `unknown` | 比率が読めない行。**欠損は解消ではない** | 入れない | 入れない（件数だけ） |

### 報告が止まったもの（`stale_reporting`）

報告義務は 0.1% 動くたびに発生する。0.5% 以上の建玉が半年間 1 度も 0.1%
動かないのは実務上ほぼ無い。にもかかわらず本番データでは:

| 最終報告からの経過営業日 | 件数 |
| --- | --- |
| 0–20 | 3,035 |
| 21–60 | 271 |
| 61–125 | 69 |
| 126–250 | 37 |
| 251–500 | 148 |
| 500 超 | 792 |

分布が明確に二峰で、間が谷。**940 件（21.6%）が 250 営業日超**、685 銘柄に
またがる。3905 では ExodusPoint が 1,423 営業日前（5.6 年）の値のまま
「報告義務中」で合計に入っていた。ある銘柄では合計が 39.77% になる。

**2 口径で持つ**（第十三轮 P0-3）。125 営業日はデータ品質のヒューリスティック
であって、公式ルールに失効期限は無い —— 変動が 0.1% に届かなければ再報告
義務は生じないので、何年も動かない古い値が「まだ正しい」可能性は法的には
残る。だから:

* `visible_*` = 新鮮（125 営業日以内）な報告義務中だけの和。因子と状態判定は
  こちら（古い値を「今の圧力」と読まない）。
* `reported_in_scope_*` = 最終報告がまだ公開範囲内の全機関の和（公式口径）。
  画面には両方出す。

「割った」（below）と「割らないまま止まった」（stale）は列を分ける。境目は
谷の位置から **125 営業日**（約半年）。

株数合計は比率合計と **同じ保有者集合**で数える。株数が 1 件でも欠けたら
合計を出さない（欠損を 0 として足すと合計が黙って小さく出る）。

### 窓内の変化は「報告と報告の差」（第十三轮 P0-4）

5 日・20 日の変化は **可視合計の差では取らない**。可視合計は機関ごと出入り
するので、0.60%→0.49% の実際の −11 万株が「−60 万株」に化ける（閾値割れで
合計から機関ごと消えるため）。正しくは同一連鎖（機関 × ファンド）の隣り合う
報告の差を積み上げる: 閾値割れは「最終報告の値までの減少」。

**窓の前に公開範囲に居なかった連鎖の起点（evt-v4）。** 初出・再参入の報告には
たいてい前回値（`PrevRptRatio`）が入っている（2025-06 以降の初出 8,832 件のうち
7,402 件が 0〜0.5% の値）。0.43% → 0.53% を「0 から 0.53%」と数えると +0.10
ポイントの変化が 5 倍に化けるので、窓内の最初の報告が述べる前回値を起点にする。
前回値が無いときだけ、最後に見えていた値（無ければ 0）。

### 訂正の 2 段階選択（第十三轮 P0-5）

同じ (連鎖, 仓位日) の中で締切以前の最新公開版を採り、その **有効版の中で
仓位日が最新** のものを現在状態とする。1 段階（公開日最新）だと、古い仓位日の
訂正が後から公開されただけで新しい仓位状態が巻き戻る。訂正はイベントには
残るが、增仓/减仓などの **行動としては数えない**。

### 連鎖 = 機関 × ファンド

同一機関が複数ファンド名義で並行報告する行が実データに 2,094 行ある。生表の
主キーにもファンド名・住所が入っており（v8）、機関単位に潰すと片方のファンド
の建玉が黙って消える。表示は機関単位に集約（`chain_count` に内訳）。

## 3. 機関実体の正規化

3 層（剥がすのは **法人形式語だけ**。`International` / `Securities` /
`Capital` / `証券` などの営業実態語は残す）:

* `institution_legal_entity` — 法的主体。**似ているだけでは統合しない**
* `institution_group` — 表示・集計用の別レイヤー。下の行は法人のまま
* `institution_alias` — 生表記 → 法的主体。人手で維持できる

統合が起きるのは 2 通りだけ:

1. 正規化（NFKC・大小文字・記号・法人格語）で **完全一致**
2. 人手の別名表に載っている

信頼度は「統合が誤りうる場合にだけ」下げる:

| `match_kind` | 信頼度 | いつ |
| --- | --- | --- |
| `exact` | 1.0 | この実体に属する生表記が 1 つだけ（統合していない） |
| `curated` | 1.0 | 人手の別名表 |
| `normalized` | 0.75 | 正規化で別の生表記と一致した |
| `aggregate` | 0.35 | `個人` など、法人ではなく別人の集合 |

### 地址不再用来拆分实体（inst-v4）

旧版把「同一规范化名称出现过多个地址」的机构按地址指纹拆成多个实体。生产十年
数据的实测否定了这个做法：

* 这样的名称有 87 个，按「股票 × 名称 × 基金」是 17,024 组。同一仓位日、同一公开日
  从不同地址报出**不同数值**（才是真正的两家并行）的只有 1 组（Citigroup Global
  Markets 的伦敦与纽约，2019 年）。同值重复则有 11,491 个仓位日 —— 地址不同几乎
  全是写法不同、搬迁，或者那一批数据没有地址栏。
* 2025-06 至 2026-07 的一括配信没有地址栏，2026-08 起的日次配信有。于是同一家
  机构被拆成 `-noaddr` 和带地址的两个实体，前者永远停在 7 月底的数值，却仍算
  「报告中」并计入合计。2026-11-20 的实测：1,132 只股票的公开持仓合计是错的；
  全市场合计 45.3 个百分点里只有 26.5 是真的，其余是重复计入或已经跌破门槛的仓位；
  「在册合计」71.5 → 33.9；显示有公开空头的股票 1,548 → 1,236 只。

现在的规则：实体只按规范化名称和人手别名表决定。`events.build_events` 在**一只
股票内**发现「同一仓位日、同一公开日、不同地址、不同数值」时，才对那一组按地址
拆开。同一份报告带地址和不带地址各入库一次的（2026-07 两种配信重叠），只留一条。

例: `モルガン・スタンレーMUFG証券株式会社`（日本）と
`Morgan Stanley & Co. International plc`（英国）は **別の法的主体**のまま、
グループ `morgan-stanley` で束ねて見られる。

`個人` は 1,863 件・133 銘柄に出るが、これは 1 つの機関ではなく複数の別人の
集合なので、1 実体として数えると機関数を誤る。

## 4. 事实量

快照只保存能和原始报告、日线逐项核对的量，不做任何合成打分。

| 量 | 定义 |
| --- | --- |
| `visible_short_ratio` / `visible_institution_count` | 近 125 个交易日内有更新、最后报告不低于 0.5% 的机构，其比例之和与家数 |
| `reported_in_scope_ratio` | 最后报告不低于 0.5% 的全部机构之和（含久未更新者，官方口径） |
| `ratio_change_5d` / `ratio_change_20d` | 窗口内逐链报告差的合计（占已发行股份的比例，见第 2 节） |
| `pressure_adv20_5d` / `pressure_adv20_20d` | 同一变化换算成股数后除以 20 日平均成交量，截断在 ±5 |
| `visible_days_to_cover` | 公开可见空头股数 ÷ 20 日平均成交量。**不是全市场的回补天数** |
| `combined_visible_days_to_cover` | （机构可见股数 + 信用卖出余额）÷ 20 日平均成交量 |
| `drawdown_52w` / `price_percentile_252` / `rel_topix_20d` / `rel_sector_20d` | 价格位置与相对收益，只作为并列的事实 |
| `parked_below_count` | 60 个交易日内最后报告停在 0.40% 至 0.50% 的机构数 |
| `data_confidence` 与理由 | 报告陈旧、可见机构少、流动性薄、价格历史短等逐项相乘 |

`data_confidence` 不再因为「机构名经规范化后与另一种写法一致」而减分。大机构几乎
都有大小写不同的写法，旧规则让有公开空头的 1,564 只股票里 1,450 只一律减分，
置信度不再能区分股票。现在只对集合名义（`個人` 等）减分。

`informed` 口径（去掉集合名义后的同一组量）仍放在 `components_json.informed` 里，
与全口径并列。

## 5. 近 20 日动向（`primary_state`）

只由公开持仓比例的净变化决定，**与股价无关**。门槛是 0.10 个百分点，也就是
法定的再报告步长。

| 状态 | 条件 |
| --- | --- |
| `building` 增加中 | 20 日净增不低于 0.10 个百分点，且近 5 日没有反向超过门槛 |
| `covering` 减少中 | 20 日净减不低于 0.10 个百分点，且近 5 日没有反向超过门槛 |
| `mixed` 方向反复 | 20 日与 5 日方向相反；或 20 日净变化不足门槛但近 5 日超过门槛 |
| `steady` 持平 | 有近期公开持仓，变化不足门槛 |
| `no_signal` | 没有近期公开持仓，也没有超过门槛的变化 |

旧版的六个状态（正常做空、低位冲突、卖压吸收、回补启动、挤空确认、背离失效）
全部取消，原因见第 12 节。补充标签只保留陈述事实的：`new_entry`、`reentry`、
`concentrated`、`multi_reduction`、`below_threshold`、`not_visible`、
`crowded_margin`、`regulated`、`earnings_near`、`thin_liquidity`、`stale_data`、
`hedge_disclosed`、`single_institution`、`parked_below`、`no_informed_reporter`。

## 6. 拥挤度（`crowding_level`）

两个事实量上的固定分档，没有权重：

| 档 | 条件 |
| --- | --- |
| 高（3） | 近期机构不少于 4 家，或公开持仓不低于 4% |
| 中（2） | 近期机构不少于 2 家，或公开持仓不低于 2% |
| 低（1） | 其余有近期公开持仓的 |
| 无（0） | 没有近期公开持仓 |

拥挤度不入库，由接口从两列现算（规则只在 `states.CROWDING_RULES` 一处）。
它是这一页唯一带有「之后往往偏弱」含义的读法，依据与限度见第 12 节。

排行的视图都按事实列排序：`crowded`（公开持仓比例）、`building` / `covering`
（20 日净变化）、`entries`（新进入或重新进入）、`days_to_cover`、`all`。
ETF 与 ETN（`ProdCat` 014、023）默认不进排行和计数：对指数连动、反向连动
受益证券的做空是套利和对冲，不是对公司的看法。REIT（013）保留并标注。

## 7. 与雷达的联动

**写入口仍只有 `alert_priority` 一处，而且现在什么都不写。** 旧版按状态加减分
的表（挤空确认 +8、回补启动 +5、卖压吸收 +4、背离失效 −6）随状态一起取消。
只剩拥挤度的「只减不加」（informed 口径机构数不少于 2 家 −2、不少于 4 家 −4，
乘以置信度），开关 `CROWDING_LINK_ENABLED = False`。空卖定位为参考信息
（2026-09-02 的决定），雷达排序不受影响；只在明确要求时才打开。

## 8. 後台任務

引け後バッチの **雷達の後ろ**:

```
空売り残高同期 → 信用・業種空売り同期 → 日足同期 → 雷達スキャン
  → rebuild_events（イベント + 最後の公開状態）
  → refresh_snapshots（銘柄 × 日のスナップショット）
  → build_signals（状態が変わった銘柄だけ）
```

雷達の後ろに置くのは、突破確認と出来高確認を事実として `components_json` に
残すため。突破の定義は雷達 1 か所に置き、空売り側で価格を再判定しない。

* イベント ID は内容から決まるので、何度走らせても同じ行に上書きされる。
  再構築は UPSERT + **掃除**: `build_version` を全行に押し、今回導出されな
  かった旧行を最後に消す（幽霊行対策。人手の別名 curated は消さない）
* 日次スナップショットは全行 + 信号 + run マーカーを **1 トランザクション**
  で公開する。途中で落ちた半端な断面が「最新」に見えることはない。ETag は
  run_id を含むので、同じ日を訂正で作り直しても 304 に化けない
* 1 銘柄の異常で全市場を止めない（例外は握って `status: error` を返す）
* 失敗したら前回の有効なスナップショットをそのまま残す（消さない）
* API は保存済みの行を読むだけ。ページを開いても全市場計算は起きない
* レーダー優先度への連動は無い（第 7 節）

## 9. 一括配信の回填について（今回の実害）

`backfill_plan` は「計画を立てた窓の中では完了」しか意味しないのに、
ワーカー側が `pending == 0` を「履歴が揃った」と同義に扱っていた。
`backfill_years` を 1 → 10 に広げた後も、空売り残高・空売り比率・信用余額は
2025-06 起点の古い計画のまま固まり、**10 年分あるアーカイブのうち 35 / 35 / 17 本**
しか取り込めていなかった（日足だけは別の機会に立て直されて 141 本入っていた）。

対策: 計画に `bulk_history_from`（月初に丸めた窓の先頭）を残し、窓が変わったら
立て直す。取り込み済みの `bulk_done` と増分レーンの位置は保つ。

## 10. 点時セマンティクスの限界（正直に）

* 機関空売り残高は 2016-08 まで遡って **開示日つき**で入っている（140 万件）。
  ただし 2025-06 より前は月次の履歴ファイルから再構成したもので、「当時その日に
  日次配信されていたか」までは検証できない。開示日そのものは J-Quants の値なので
  点時セマンティクスは守れるが、「配信の遅れ」までは再現していない
* 業種・市場区分は現在値。過去の区分変更は再現していない
* 信用取引残高は週次。日次の混雑度は週の値を引き伸ばしている

## 12. 证据：为什么取消打分与旧状态，为什么只留拥挤度

三次互相独立的检验，方向一致。

**(1) 第十二轮走步验证**（2017-01 至 2026-06，62,609 个信号，16 个窗口）。所有
状态在所有持有期都跑输 TOPIX，权重最高的「卖压吸收」最差；可见机构数 0 / 1 /
2–3 / 4+ 对应的 20 日超额是 −1.10% / −1.42% / −1.98% / −2.85%，是唯一稳定的
单调关系。详见 `docs/round-12-delivery.md` 第 12 节。

**(2) 2026-09 事件研究**（2023-06 起 66 万个事件）。增仓、减仓、回补之后都是负
超额，回补事件最差（−2.56%）；仓位水平越高越差。

**(3) 线上保存的每日快照**（2026-08-03 至 2026-11-20，74 个交易日，当时的判定
原样保存，因此是真正的样本外记录）。公开日次一交易日开盘买入、持有 20 个交易日，
相对同一市场区分的中位数：

| 旧版的分组 | 20 日平均超额 |
| --- | ---: |
| 行为分最高的五分之一 | −1.39% |
| 行为分其余四档 | +0.16% 至 −0.30% |
| 卖压吸收 | −1.47% |
| 挤空确认 | −1.54% |
| 回补启动 | −0.89% |
| 背离失效 | −0.77% |

旧版排在最前面的，正是之后最弱的一组。标签本身也与数据不符（2026-11-20）：
「背离失效」311 行里 64 行 20 日其实是净减少；「低位增空不跌」241 行里 201 行
空头没有增加，170 行跑输大盘；回补视图 287 行里 170 行分数封顶在 100，实际按
代码顺序排列。

把事件表按机构名重新合并（去掉第 3 节说的重复）后，对 18 个断面（每 3 个交易日
取一个）按拥挤度分档：

| 拥挤度 | 20 日平均超额 | 中位数 |
| --- | ---: | ---: |
| 无 | +0.56% | +0.19% |
| 低 | +0.40% | −0.17% |
| 中 | −0.15% | −0.46% |
| 高 | −1.22% | −1.70% |

同一批数据里，回补天数没有这种关系（不足 1 天的一组最差，7 天以上的一组反而
为正），所以回补天数只作为事实展示，不进拥挤度。

**限度。** 第 (3) 项只有三个半月，20 日窗口互相重叠，独立样本大约只有 3 个，
单看它不构成强证据。拥挤度的读法靠的是三项方向一致，而不是其中任何一项的幅度。
它是「之后一段时间往往弱于同板块」的统计关系，不是买卖信号，也没有按这段样本
调过任何门槛（分档用的就是检验时预先定的区间）。

**验证方法。** 空卖模块不在生产跑走步回放（2026-09-02 的决定，也是一次内存耗尽
事故的教训）。新语义由 `tests/test_short_monitor_rework.py` 的不变量测试钉住；
对真实数据的前后对比，是把新模块源码经标准输入送进生产容器、只读地逐股计算，
不落文件、不写库。
