# 第十二轮交付报告 — 机构空卖行为监控

分支 `short-monitor`。对应 `增量任务V1.md` 全篇。

## 0. 这一轮最重要的一件事

**回填计划被永久冻结，10 年档案里只取到了 35 个文件。**

`backfill_plan` 的语义是「在**立计划时的那个窗口内**已全部取完」，但 worker 把
`pending == 0` 当成了「历史齐了」：

```python
pending = checkpoint.get("bulk_pending")
if pending is None and not checkpoint.get("last_synced_date"):
    plan = engine.backfill_plan(dataset)      # 一旦有了 last_synced_date 就再也不重建
```

`backfill_years` 从 1 改成 10 之后，日线因为别的机会被重新规划过（141 个文件，
回到 2016-08），而空卖残高 / 空卖比率 / 信用余额 / 决算摘要仍停在 2025-06 起点的
旧计划上：**35 / 35 / 17 / 39 个文件**，而 `/bulk/list` 实际返回 142 个。

同一个数据库里，一半是 10 年、一半是 14 个月，而且每天都报告「同步成功」。

修复：计划里记下 `bulk_history_from`（按月对齐的窗口起点），窗口变了就重建，
已取的 `bulk_done` 和增量位置保留。修复后四个数据集全部自动补到 2016-08。

> 这与上一轮「`pending=0` 被当成完成」是同一形状的第二次出现。这次把窗口
> 本身写进检查点，而不是只记「做完了没有」。

## 1. J-Quants 实际提供了哪些字段

见 [`docs/short-monitor.md` §1](short-monitor.md)。要点：

* CSV 有 14 列，其中 `SSAddr` / `DICName` / `DICAddr` 之前被丢弃。`DICName` 是
  投资一任契约的相手方，是区分「报告主体」与「实际运用者」的唯一线索 —— 在跑
  10 年回填**之前**补进 schema（否则要重来一遍）。
* `Notes` 里 40,753 条明写「顧客取引に係るヘッジポジション」。这类持仓不能当作
  方向性看空来读，打 `is_hedge_disclosed` 标记并在界面显示。
* **`securities` 没有发行股数**。但比率和股数报告里都有，所以指标不需要它 ——
  这也是把股数按 ADV20 归一化的原因。
* 开示滞后实测 1–7 个交易日，众数 2 日，次为 4 日。

## 2. 重新进入与公开义务消失怎么处理

* `new` / `reentry` 分开：该机构在这只股票上**曾经**处于报告义务中，再次进入就是
  `reentry`。混在一起的话「机构回来了」这个最想看的事件会被埋进「新规」。
* 跌破门槛写成 `visibility_status = below_public_threshold` +
  `exact_position_known = False`，保留最后已知值。**不写 0，不画到 0。**
  只有明确报告为 0 的才是 `closed`。
* 订正保留原报告，另一条打 `correction`。断面取「截止日之前最新的公开日」，
  所以订正公开之前的断面不会漏入订正后的值。

## 3. 为什么公开可见空头不等于总空头

报告义务是事件驱动的：超过 0.5% 才产生义务，之后每变动 0.1% 报一次，跌破 0.5%
报最后一次就消失。所以 0.5% 以下的持仓**从来就看不见**，跌破之后的持仓是
「≤ 该值且未知」。

3905 的实测：把 13 家的最新值直接相加得 **4.64%**，其中处于报告义务中的只有
1 家 **1.23%**。其余全是跌破门槛时的最终报告，加总等于在数不存在的空头。

因此库、接口、界面里都没有 `total_short_*`，只有 `visible_*` / `reported_*`。

## 4. 卖压是否被吸收怎么判断

```
raw_damage = -min(相对TOPIX, 相对业种) / pressure_adv20
absorption = 100 - percentile(raw_damage, 当日全市场)
```

* 压力低于 ADV20 的 2% 就不下判断（不拿小分母做除法）
* 相对收益取市场与行业里**较弱的一个**（不挑对自己有利的）
* 5 日与 20 日方向不一致则打 0.7 折
* 仍在创新低则打 0.4 折 —— 还在创新低，说明卖压仍然有效

**用横截面分位，而不是从美股搬来的绝对阈值。** 日股上没有验证过的阈值，
换成「当天全市场里排第几」至少是有明确含义的基准。

## 5. 正常做空 与 空头—价格背离 的区分

同样的压力下：

| 价格反应 | 判定 |
| --- | --- |
| 明显跑输市场 | 正常做空（压力有效） |
| 只是小跌 | 出现承接 |
| 与市场持平或上涨 | 强背离候选 → 卖压吸收 |
| 跌破长期支撑且相对继续恶化 | 背离失效 |

## 6. 回补启动怎么判断

公开空头股数下降（按 ADV20 归一化）+ 相对转强。**不要求正式突破** ——
突破是「挤空确认」才要求的。集中在 1–2 家的减仓打 0.75 折。

## 7. 「挤空确认」的严格条件

五个条件**同时**满足才给：

1. 公开空头明显下降（20 日与 5 日都 ≤ −3% ADV20）
2. 公开可见回补天数 ≥ 1.0
3. 雷达判定为突破确认状态
4. 出来高确认
5. 相对 TOPIX 与相对业种同时转强

并且界面上必须带说明：这是基于公开空头变化和价格行为的模型分类，不表示掌握
全部市场空头仓位。

## 8. 3905 的结果

见 [`docs/short-monitor-3905-audit.md`](short-monitor-3905-audit.md)。

结论是 **背离失效**，不是利好。这正是指令书 §十五要的：以真实数据为准，

## 9. 评分与雷达连动

`institutional_short_behavior_score` 是 0–100 的研究排序分，不是上涨概率。
`SCORE_VALIDATED = False` / `GATES_VALIDATED = False`，接口的 `validated` 字段
直接把这件事告诉前端，页面据此显示「尚未通过历史验证」。

雷达连动**只写 `alert_priority` 一个字段**，最大 ±8 分再乘数据置信度，
素值保留在 `alert_priority_base`。`base_quality` / `breakout_confirmation` /
`intrinsic_strength` 一个都不碰。影子分在响应里叫 `shadow_score`。

## 10. 顺带修掉的三个问题

| 问题 | 影响 |
| --- | --- |
| 报告陈旧度按**交易日历末尾**算 | 日历同步到 1 年后，昨天的报告显示「247 个交易日前」，全市场数据置信度被一律压低（3905 是 0.40）。置信度同时影响排序和状态判定 |
| 新任务在首次运行前算「缺失」 | 加一个任务就让容器 unhealthy 到该任务首次执行为止，`deploy.sh --wait-timeout 180` 直接失败 |
| 重启中断的任务算「降级」 | 每次重启后，最长首次延迟（maintenance 300 秒）内容器都 unhealthy |

后两个是既有问题，加新任务时才暴露出来。

以及一个我自己新做出来的：**把水位当成变化显示**（`公开可见空头 +5.23%`）。
和上一轮修过的是同一形状，这次是新写的代码。加了无符号的 `fmtPctLevel`。

还有一个：i18n 字典里既有的条目用的是**不带引号的键**（`加载中:`），
`grep "'加载中'"` 找不到，于是我加了重复键；tsc 报 TS1117 之后我又误删了原来的
那一份。加了同时识别两种写法的检测脚本进 CI。

## 13. 明确没有做的

* **权重与阈值未经历史验证。** `GATES_VALIDATED` / `SCORE_VALIDATED` 都是 False，
  接口和页面都照实说。不写「日股最佳参数」。
* **机构空卖报告的开示日只在 2025-06 之后是完整的。** 之前的断面由一括配信的
  历史文件重建，无法验证「当时那天是否已经发布」。这是走步验证结论的硬限制。
* **业种与市场区分用的是当前值**，没有点时版本。
* **信用残高是周次**，日度拥挤度是把周值拉平的。
* **新闻催化剂无法回溯到同样密度**，历史再生时按「没有」处理，不按中立处理。
