# 第十二轮交付报告 — 机构空卖行为监控

分支 `short-monitor`。对应 `增量任务V1.md` 全篇。

---

## 0. 这一轮最重要的一件事

**回填计划被永久冻结，10 年档案里只取到了 35 个文件。**

`backfill_plan` 的语义是「在**立计划时的那个窗口内**已全部取完」，但 worker 把
`pending == 0` 当成了「历史齐了」：

```python
pending = checkpoint.get("bulk_pending")
if pending is None and not checkpoint.get("last_synced_date"):
    plan = engine.backfill_plan(dataset)      # 一旦有了 last_synced_date 就再也不重建
```

`backfill_years` 从 1 改成 10 之后，日线因为别的机会被重新规划过（141 个文件，
回到 2016-08），而空卖残高 / 空卖比率 / 信用余额 / 决算摘要仍停在 2025-06 起点的
旧计划上：**35 / 35 / 17 / 39 个文件**，而 `/bulk/list` 实际返回 142 个。

同一个数据库里，一半是 10 年、一半是 14 个月，而且每天都报告「同步成功」。

修复：计划里记下 `bulk_history_from`（按月对齐的窗口起点），窗口变了就重建，
已取的 `bulk_done` 和增量位置保留。修复后四个数据集全部自动补到 2016-08。

> 这与上一轮「`pending=0` 被当成完成」是同一形状的第二次出现。这次把窗口
> 本身写进检查点，而不是只记「做完了没有」。

## 1. J-Quants 实际提供了哪些字段

见 [`docs/short-monitor.md` §1](short-monitor.md)。要点：

* CSV 有 14 列，其中 `SSAddr` / `DICName` / `DICAddr` 之前被丢弃。`DICName` 是
  投资一任契约的相手方，是区分「报告主体」与「实际运用者」的唯一线索 —— 在跑
  10 年回填**之前**补进 schema（否则要重来一遍）。
* `Notes` 里 40,753 条明写「顧客取引に係るヘッジポジション」。这类持仓不能当作
  方向性看空来读，打 `is_hedge_disclosed` 标记并在界面显示。
* **`securities` 没有发行股数**。但比率和股数报告里都有，所以指标不需要它 ——
  这也是把股数按 ADV20 归一化的原因。
* 开示滞后实测 **1–13 个交易日**，众数 2 日，次为 4 日。用 `position_date` 当信号日就是把这些天的未来信息灌进过去。

## 2. 重新进入与公开义务消失怎么处理

* `new` / `reentry` 分开：该机构在这只股票上**曾经**处于报告义务中，再次进入就是
  `reentry`。混在一起的话「机构回来了」这个最想看的事件会被埋进「新规」。
* 跌破门槛写成 `visibility_status = below_public_threshold` +
  `exact_position_known = False`，保留最后已知值。**不写 0，不画到 0。**
  只有明确报告为 0 的才是 `closed`。
* 订正保留原报告，另一条打 `correction`。断面取「截止日之前最新的公开日」，
  所以订正公开之前的断面不会漏入订正后的值。

## 3. 为什么公开可见空头不等于总空头

报告义务是事件驱动的：超过 0.5% 才产生义务，之后每变动 0.1% 报一次，跌破 0.5%
报最后一次就消失。所以 0.5% 以下的持仓**从来就看不见**，跌破之后的持仓是
「≤ 该值且未知」。

3905 的实测（10 年全量）：把 24 家的最新值直接相加得 **9.62%**，其中直近有更新、
处于报告义务中的只有 1 家 **1.23%**。其余是跌破门槛 17 家、解消 5 家、
**报告已停止 1 家**（最后一次报告在 1,423 个交易日前）。加总等于在数不存在的空头。

因此库、接口、界面里都没有 `total_short_*`，只有 `visible_*` / `reported_*`。

## 4. 卖压是否被吸收怎么判断

```
raw_damage = -min(相对TOPIX, 相对业种) / pressure_adv20
absorption = 100 - percentile(raw_damage, 当日全市场)
```

* 压力低于 ADV20 的 2% 就不下判断（不拿小分母做除法）
* 相对收益取市场与行业里**较弱的一个**（不挑对自己有利的）
* 5 日与 20 日方向不一致则打 0.7 折
* 仍在创新低则打 0.4 折 —— 还在创新低，说明卖压仍然有效

**用横截面分位，而不是从美股搬来的绝对阈值。** 日股上没有验证过的阈值，
换成「当天全市场里排第几」至少是有明确含义的基准。

## 5. 正常做空 与 空头—价格背离 的区分

同样的压力下：

| 价格反应 | 判定 |
| --- | --- |
| 明显跑输市场 | 正常做空（压力有效） |
| 只是小跌 | 出现承接 |
| 与市场持平或上涨 | 强背离候选 → 卖压吸收 |
| 跌破长期支撑且相对继续恶化 | 背离失效 |

## 6. 回补启动怎么判断

公开空头股数下降（按 ADV20 归一化）+ 相对转强。**不要求正式突破** ——
突破是「挤空确认」才要求的。集中在 1–2 家的减仓打 0.75 折。

## 7. 「挤空确认」的严格条件

五个条件**同时**满足才给：

1. 公开空头明显下降（20 日与 5 日都 ≤ −3% ADV20）
2. 公开可见回补天数 ≥ 1.0
3. 雷达判定为突破确认状态
4. 出来高确认
5. 相对 TOPIX 与相对业种同时转强

并且界面上必须带说明：这是基于公开空头变化和价格行为的模型分类，不表示掌握
全部市场空头仓位。

## 8. 3905 的结果

见 [`docs/short-monitor-3905-audit.md`](short-monitor-3905-audit.md)。

结论是 **背离失效**，不是利好。这正是指令书 §十五要的：以真实数据为准，
不强行把 3905 判成有利。

## 9. 评分与雷达连动

`institutional_short_behavior_score` 是 0–100 的研究排序分，不是上涨概率。
`SCORE_VALIDATED = False` / `GATES_VALIDATED = False`，接口的 `validated` 字段
直接把这件事告诉前端，页面据此显示「尚未通过历史验证」。

雷达连动**只写 `alert_priority` 一个字段**，最大 ±8 分再乘数据置信度，
素值保留在 `alert_priority_base`。`base_quality` / `breakout_confirmation` /
`intrinsic_strength` 一个都不碰。影子分在响应里叫 `shadow_score`。

## 10. 顺带修掉的问题

| 问题 | 影响 |
| --- | --- |
| 报告陈旧度按**交易日历末尾**算 | 日历同步到 1 年后，昨天的报告显示「247 个交易日前」，全市场数据置信度被一律压低（3905 是 0.40）。置信度同时影响排序和状态判定 |
| 新任务在首次运行前算「缺失」 | 加一个任务就让容器 unhealthy 到该任务首次执行为止，`deploy.sh --wait-timeout 180` 直接失败 |
| 重启中断的任务算「降级」 | 每次重启后，最长首次延迟（maintenance 300 秒）内容器都 unhealthy |
| 新任务与引け後批次抢单写者 | 同一个重建跑两处，9 分钟连续写入互锁，`database is locked` 连挂两次 |
| 回放一次读 10 年 K 线 | 1,010 万行进内存，2 分钟 OOM，日志只留一行进度，看起来像「正常结束了」 |
| **报告停止的机构仍计入合计** | 见 §3。全市场 940 件（21.6%）超过 250 个交易日，某只股票加总出 39.77% |
| 说明文数了合计里没算的家数 | 「报告义务中 2 家，合计 1.23%」——1.23% 只有 1 家 |
| 验证的比较基准是永不出现的组 | `no_signal` 从不作为信号发出，四个问题里有两个永远 `insufficient_data`（我自己设计的测试答不了我自己提的问题） |

中间三个是既有问题，加新任务/跑真实规模时才暴露出来。

以及一个我自己新做出来的：**把水位当成变化显示**（`公开可见空头 +5.23%`）。
和上一轮修过的是同一形状，这次是新写的代码。加了无符号的 `fmtPctLevel`。

还有一个：i18n 字典里既有的条目用的是**不带引号的键**（`加载中:`），
`grep "'加载中'"` 找不到，于是我加了重复键；tsc 报 TS1117 之后我又误删了原来的

## 12. 历史验证 — **结论是否定的**

走步验证：2017-01 至 2026-06，每 20 个交易日取一次断面，115 个评估日，
**62,609 个信号**（可评估 61,680），16 个走步窗口。点时语义由信号侧保证
（`source_cutoff` 用公开日），不打乱日期。

### 各状态的 20 日相对 TOPIX 中位超额

| 状态 | n | 1日 | 3日 | 5日 | 10日 | **20日** | 20日胜率 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| **（全部信号，基准）** | **61,680** | | | | | **−1.77%** | **48.1%** |
| normal_shorting | 21,702 | −0.14% | −0.28% | −0.45% | −0.75% | **−1.60%** | 48.3% |
| divergence_failed | 10,873 | −0.28% | −0.23% | −0.35% | −0.80% | **−1.63%** | 49.7% |
| covering_start | 10,638 | −0.16% | −0.35% | −0.55% | −0.97% | **−2.08%** | 46.7% |
| absorption | 9,397 | −0.22% | −0.42% | −0.77% | −1.18% | **−2.55%** | 45.0% |
| low_conflict | 9,070 | −0.24% | −0.22% | −0.36% | −0.62% | **−1.51%** | 50.6% |

**每一个状态在每一个持有期都跑输 TOPIX，而且随持有期加深。**

### 指令书 §十六 点名的四个问题

| 问题 | 答案 |
| --- | --- |
| 卖压吸收候选 是否优于普通低位股 | **否。** 差 **−1.04%**，16 个窗口里只有 **2 个** absorption 更好 |
| 回补启动 是否优于基准 | **否。** 差 **−0.31%**（−2.08% vs 基准 −1.77%） |
| 挤空确认 是否优于普通技术突破 | **无法回答。** 回放里 n=0 —— 挤空确认要求雷达的突破确认，而回放不重建雷达 |
| 背离失效 是否确实更差 | **否，反而略好。** +0.14%（−1.63% vs 基准 −1.77%），胜率 49.7% 是第二高 |
| 机构重新进入 / 机构轮换 单独是否有预测价值 | **否。** reentry −0.43%（n 37,938 vs 23,742）、rotation −0.81%（n 11,828 vs 49,852）、new_entry −0.14%，三个都是 `not_predictive` |

### 两个状态的方向是反的

设计上 `absorption` 是**看多候选**（卖压被吸收），`divergence_failed` 是
**看空状态**（空头重新取得控制）。实测：

* `absorption` −2.55%、胜率 45.0% —— **五个状态里最差**
* `divergence_failed` −1.63%、胜率 49.7% —— 比基准还**略好**

不是「幅度不够」，是**排序整个反了**。这比「没有预测力」更值得记下来：
按当前定义，「卖压被吸收」这件事在日股上不是转强的前兆。

`absorption` 在 16 个窗口里的表现不是噪声，是稳定地更差：

```
2018H1 −3.69% vs −1.71%      2022H1 −0.66% vs −0.01%
2018H2 −2.52% vs −1.40%      2022H2 −1.75% vs −1.08%
2019H1 −2.38% vs −0.57%      2023H1 −3.69% vs −3.86%  ← absorption 较好
2019H2 −2.56% vs −0.51%      2023H2 −3.46% vs −3.28%
2020H1 −5.17% vs −0.21%      2024H1 −4.02% vs −0.31%
2020H2 −1.53% vs −1.86%  ←   2024H2 −1.78% vs −1.57%
2021H1 −2.51% vs −2.11%      2025H1 −1.54% vs −1.51%
2021H2 −2.78% vs −2.15%      2025H2 −3.51% vs −2.87%
```

### 两个真实的单调性（方向都和设计相反）

**可见机构数越多，之后越差：**

| 可见机构数 | n | 20日超额 |
| --- | ---: | ---: |
| 0 | 3,488 | −1.10% |
| 1 | 27,185 | −1.42% |
| 2–3 | 20,911 | −1.98% |
| 4+ | 10,096 | −2.85% |

单调。「多家机构在做空」本身就是一个有效的看空信号 —— 这与本模块的出发点
（机构在低位加空 → 卖压被吸收 → 回补）方向相反。

**公开可见回补天数越高，之后**越不差**：**

| 分位 | n | 20日超额 |
| --- | ---: | ---: |
| q1（最低） | 15,130 | −2.47% |
| q2 | 11,637 | −1.74% |
| q3 | 11,637 | −1.62% |
| q4 | 11,638 | −1.50% |
| q5（最高） | 11,638 | −1.48% |

这是唯一一个方向与设计一致的排序，但幅度小（q1→q5 差 1.0%），且全都是负的。

### 市场区分：主要是小盘效应

| 市场 | n | 20日超额 | 胜率 |
| --- | ---: | ---: | ---: |
| プライム (0111) | 28,909 | −1.03% | 52.1% |
| スタンダード (0112) | 14,891 | −2.49% | 44.3% |
| グロース (0113) | 10,447 | −4.02% | 41.3% |

### 这个结果意味着什么

1. **机构公开空卖发生变动的股票，整体跑输市场**，各状态之间的差别远小于
   这个整体效应。
2. **`absorption` 权重最高（0.30），但表现最差**，而且比它本该优于的
   `low_conflict` 更差，16 个窗口里 14 个更差；看多状态与看空状态的排序
   整个反了。这是对设计前提的直接否定，不只是「参数没调好」。
3. **`squeeze_confirmed` 无法验证** —— 回放不重建雷达的突破确认，所以 n=0。
   要验证必须先把雷达也放进回放，这一轮没做。
4. 三个辅助标签（重新进入 / 轮换 / 新规进入）**单独都没有预测价值**。

### 因此没有做的事

按指令书 §十六「如果某项没有稳定预测能力，不要因为叙事好听而保留高权重」，
本该下调 `absorption` 的权重。**但没有改。** 理由是：根据同一次回测调权重
就是对这次回测拟合，而这次回测的结论不是「权重不对」，是
**「这套状态整体没有正向预测力」**。调权重只会把一个未经验证的参数换成
另一个未经验证的参数。

正确的处理是照实写下来，并且保持 `SCORE_VALIDATED = False`、
`GATES_VALIDATED = False` —— 界面上也照实显示「尚未通过历史验证」。
这套分数目前只能当作**描述性的分类与排序**，不能当作预期超额收益的排序。

### 这次验证本身的两个缺陷（也要写下来）

* **比较基准一开始是 `no_signal`**，而 `no_signal` 从不作为信号发出，
  所以四个问题里有两个永远返回 `insufficient_data`。已改为与母集团比较。
* **回放不加载信用余额**，所以 `crowded_margin` 标签在 61,680 条里出现 0 次，
  信用拥挤这条完全没被验证。

## 13. 明确没有做的

* **权重与阈值未经历史验证。** `GATES_VALIDATED` / `SCORE_VALIDATED` 都是 False，
  接口和页面都照实说。不写「日股最佳参数」。
* **机构空卖报告的开示日只在 2025-06 之后是完整的。** 之前的断面由一括配信的
  历史文件重建，无法验证「当时那天是否已经发布」。这是走步验证结论的硬限制。
* **业种与市场区分用的是当前值**，没有点时版本。
* **信用残高是周次**，日度拥挤度是把周值拉平的。
* **新闻催化剂无法回溯到同样密度**，历史再生时按「没有」处理，不按中立处理。
